基于共享 ItemGame 0.3.0 Scene3D 的 2–7 阶魔方游戏。使用程序化暗石方块、黄铜边缘和六色宝石面，无需外部贴图或模型包。

```powershell
# 在仓库根目录执行
npm run build:cube
python tests/test_scene3d.py
npm run test:cube
python tools/preview-cube.py
```

将 [dist/item.t3e.txt](dist/item.t3e.txt) 的完整内容导入 TRP3 Extended，把物品添加到背包，右键“解开魔方”。目标沿用 WoW 12.1.0 / TRP3E 1061（2.3.5）；当前为待客户端验收的测试候选。

## 操作与游戏规则

- 右键拖动观察；滚轮缩放；重置视角恢复默认镜头。
- 左键点选方块，选择 X/Y/Z 轴和层，按 ±90° 转层；也可左键拖动方块，根据屏幕拖动方向选择转轴与层。
- 层号沿轴从负到正排列。正转采用右手规则；J/K 分别正转/反转，Z 撤销。
- 支持所有内层；2阶没有内层，3–7阶可通过层号或拖动选择。阶数上限由本项目容量预算决定。
- 打乱开始新挑战，第一次转层开始计时。六个面各自同色即复原，整体转动整个魔方也视为同一完成状态。
- 每阶保存最佳无辅助挑战时间及对应步数。撤销或回放会把本局标记为辅助练习，不刷新挑战最佳成绩。
- “回放复原”逆向执行完整的本局操作记录，可中途停止。它不是通用最短解求解器，也不支持外部拍照局面导入。
- Esc 暂停/继续；关闭保存。切阶、打乱和清空有局面替换确认。写入失败时保留窗口。

存档保存初始阶数和最多2000步精确操作序列，重建整数位置与朝向。动画在完整90度转动结束后提交；关闭时未完成的转动不写入存档，重开回到上一完整步。打乱序列也在记录中，因此任意已保存局面都可回放复原。暂停和动画不产生累计浮点排列误差。

## 文件与解耦

| 文件 | 职责 |
| --- | --- |
| `src/puzzle.lua` | N阶排列、整数旋转、打乱与完成判定；无显示依赖 |
| `src/geometry.lua` | 本游戏的方块与宝石配色/几何 |
| `src/ui.lua` | 本游戏界面、菜单与按钮 |
| `game.lua` | 游戏流程、动画、输入意图与保存 |
| `../../framework/item-game/math3d.lua` | 通用向量、仿射变换、射线与扫掠 |
| `../../framework/item-game/scene3d.lua` | 通用3D场景、投影、拾取与空间查询 |
| `../../framework/item-game/view3d.lua` | 原生纹理顶点、对象池、鼠标和生命周期适配 |

七阶由218个外壳方块及一个转动父节点组成，共219个节点，未创建不可见内部小块。经典皮肤2190个显示面，海潮皮肤3956个显示面；场景预算256节点、4096面。静止时复用投影结果；视角或变换变化时更新。

完整接口和限制见 [3D开发指南](../../docs/ITEM-GAME-3D.md)。当前不提供GPU深度缓冲或复杂刚体；魔方是三维几何与输入测试项目，不代表大规模三维场景已达到客户端性能目标。

## 客户端验收

1. 导入后从背包启动，检查六色、边缘和转层中间帧；3阶与7阶各转一次外层及内层。
2. 不同 UI 缩放下点选、拖转和右键观察；拖出视口后松开，确认不会持续拖动。
3. 打乱、转层、暂停、关闭、重开，核对局面与时间；重载界面后再核对物品变量。
4. 使用回放复原确认归一；记录7阶转动的客户端帧耗时。模型/浏览器模拟的耗时不算实机证据。

本地预览运行实际 Lua 源码和标注为 mock 的宿主，浏览器显示实际原生顶点输出。它可用于界面检查，不能替代以上客户端路径。

## 烟花奖励与性能试验

手动复原和回放复原完成时各触发一次烟花；重新载入已完成局面不重播，烟花不写入存档。星辉礼花、奥术星环、鎏金垂柳、翡翠喷泉和连环爆裂使用不同发射方向、速度、阻力、寿命与多段爆发。火箭尾焰随发射器升空，已出生粒子继续独立运动。

右上角“烟花试验”打开控制面板，可选择单式、五式组合及低/标准/高密度。四阶段对照依次运行空场、低密度、标准和高密度，各预热1秒、采样5秒，总计约24秒。对照期间固定当前阶数、镜头和魔方，解谜计时暂停；测试不改变局面。暂停中断当前测试，停止会清场；导出日志保留已完成/中断阶段。

面板显示宿主FPS、帧耗时P95、粒子更新/投影/绘制均值、数量、峰值和丢弃数。当前预算1536粒子、24发射器、每步768次生成。高密度故意可能触及预算，丢弃数据用于确认退化行为。各阶段粒子计数包括预热，计时分位数只统计采样区间。

`src/fireworks.lua` 只编排本游戏的烟花和对照；三维发射、粒子运动、裁剪、池复用及绘制属于共享引擎。浏览器将原生star4纹理近似为渐变光点，不能据此认定WoW纹理视觉或帧率通过。

算法优化前后数据见 [性能对比](performance/README.md)，程序化复测命令为 `python tools/benchmark-scene3d.py`。
