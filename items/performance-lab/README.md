# IG 引擎性能测试台

这是已构建的**测试候选道具**，包含 ItemGame 引擎、测试程序、原生工作流和内部对象。0.1.1 已完成首轮实机自动基准；当前 0.2.0 加入有界纹理粒子、发射器和专项压力阶段，包含此前共享模型、启动、BGM 与关闭修复，待游戏内复测。

开发与排错：[游戏开发指南](../../docs/ITEM-GAME-DEVELOPER-GUIDE.md) · [维护指南](../../docs/ITEM-GAME-MAINTENANCE.md) · [FAQ](../../docs/ITEM-GAME-FAQ.md)。

## 直接使用

1. 打开 [dist/item.t3e.txt](dist/item.t3e.txt)，复制完整内容。
2. 在 TRP3 完整数据库中导入，从数据库把主道具添加到背包；原生交易收到实例时可直接使用。
3. 按 TRP3 原生安全提示审阅这份道具的脚本和安全宏。宿主已信任的本人道具可直接使用。
4. 更新旧版时重新导入同根 ID 的构建版本 6，执行一次 `/reload` 清理旧运行状态，再在 TRP3 背包右键使用。聊天会依次显示 `[IG 1/3]`、`[IG 2/3]`、`[IG 3/3]`，最后分别显示构建版本和道具修订。失败会显示 `[IG INJECTION]`、`[IG BOOTSTRAP]` 或 `[IG OPEN]`，并保留到 `IG_BOOT_STATUS_V1`。
5. 点击“自动基准”。默认 24 个阶段，每阶段 2 秒预热、10 秒采样，总计约 5 分钟。
6. 测完点“复制日志”，Ctrl+A、Ctrl+C，在游戏外保存为 UTF-8 的 `run.ndjson`。按钮不会直接创建电脑文件。

只需要已有的 TRP3/Extended；Music 的自定义 MIDI 功能可选安装 Musician，本体游戏、Sound、内置 BGM 不依赖它。

### 0.1.1 启动修复

旧版宏约 731 字节，超过 TRP3 宏编辑器的 **255 字节**限制，且没有按延时注入链编排。新版入口固定为：

```text
1. 执行宏命令（253 字节，只准备一次性注入）
2. 延时 0.1 秒
3. 执行限定 Lua（检查注入并加载引擎）
```

已在新版导入包中装配，无需手工添加节点。需要核对时可查看 [短宏](dist/bootstrap-macro.txt) 和 [第三步 Lua](dist/bootstrap-launch.lua)。宏不再依赖前置令牌或在宏执行期间创建 GUI；它只匹配本根物品，限定脚本不会获得全局能力。注入用完立即恢复，未被使用则两秒后恢复；若其他插件已接管入口，不覆盖对方入口，原注入器失活。

三步顺序和长度限制由原生工作流生成器/延时函数及 Lua 5.1 模拟检查覆盖；0.1.1 实机日志也确认窗口启动和自动负载运行。键盘归还、重登存档、交易和退出清理仍需分别验收。

### 0.1.2 BGM 修复与复测

首轮日志记录 `Sound_EnableMusic=0`；旧 BGM 使用 Music 通道，因此音效正常而音乐启动失败。新版原生 BGM 默认使用 **SFX**，仍遵守总声音/SFX 开关和音量，不修改全局 CVar。曲目可显式设置 `channel: "Music"` 跟随魔兽音乐设置；只接受 SFX/Music。

导入当前版本后直接点“BGM测试”，确认实际有声音，再检查暂停/继续、切换阶段和关闭后的停止。成功提示只代表播放请求被接受；没有听到仍需反馈日志，不必为了这一项重跑完整基准。

| reason | 意义 / 检查 |
| --- | --- |
| all_sound_disabled / master_volume_zero | 总声音关闭或主音量为 0 |
| channel_disabled / channel_volume_zero | 所选通道关闭或音量为 0；看日志 channel 确定 SFX 或 Music |
| sound_not_started | API 没返回有效播放结果/句柄，核对文件 ID 与客户端 |
| sound_unavailable / sound_api_error | 缺少接口或调用抛错 |
| no_fallback_track / invalid_music_channel | 没有内置回退资源或通道配置非法 |

新日志 `music.playback` 包含 trackId/fileID/channel/ok/reason 和可取得的 `audio.cvars`；`check.music` 保存单项结果。分析报告显示音频诊断，资源统计也提供 musicState/musicChannel/musicError。Musician 为独立可选测试，本轮原生 BGM 修复不代表它已通过验收。

### 0.1.3 Esc 与关闭修复

Esc 在普通、接管和暂停状态都关闭主界面；文本框有焦点时先返回主界面，再按 Esc 关闭。右上角 X 可直接关闭整个游戏，日志面板和标题拖动区不再遮住它。暂停使用“暂停/继续”。

退出先隐藏窗口、释放键盘，再保存和清理。统计、存档或日志异常不会中断剩余关闭步骤；错误保留在 cleanup.* 日志中。复测主界面 Esc、接管后 Esc、暂停后 Esc、日志两次 Esc、日志中 X，以及关掉后重新打开。

### 0.1.4 启动后立即退出修复

TRP3 编辑器保存自动递增 MD.V；旧引擎把它与代码内构建版本比较，造成刚显示 [IG 3/3] 就以 definition_changed 退出。现改为与启动时的修订号比较，并保留运行中修订/清单变化检测。日志 run.start 记录 objectRevision，聊天显示两个版本；不需要手工回退 MD.V。

复测：导入启动后等待数秒，确认窗口仍在；关闭后重开；在原生编辑器保存一次，再使用道具。实际运行中修改定义仍应关闭，并提示 [IG STOP]。

## 输入、关闭与存档

- 默认按键只读/透传。点击“战斗试跑”，再点“接管/释放”：A/D 或方向键移动，Space 跳跃，J 近战，K 发射弹体。
- Esc 关闭游戏；日志/曲目输入面板有焦点时先返回，第二次 Esc 关闭。“暂停/继续”暂停或恢复场次。
- 进入地下城、团队副本、场景战役、战场、竞技场或 WoW 战斗时自动关闭；住宅不按普通副本关闭，脱战后不自动重开。
- 主道具被交易、消耗或删除时停止写入并回收场次；主道具不能堆叠。
- `IG_SAVE_V1` 保存测试进度与操作记录，`IG_SAVE_BACKUP_V1` 为上一有效快照；`IG_PERF_LOG_V1` 保存最近日志。
- 每个性能阶段结束自动保存日志；关闭窗口也保存。下次打开用“上次日志”取回；启动故障提示另保存在 `IG_BOOT_STATUS_V1`。
- 变量写入发生在 TRP3 内存中，磁盘持久化遵循 WoW SavedVariables 生命周期，不能用它宣称即时刷盘成功。

材料发放/消耗有操作记录和实际数量核对；不确定的结果不会自动重试。装备独立实例保留 `IG_EQUIP_V1` 属性，右键装备可查看；角色装备规则不是这个性能项目的目标。

## 日志怎么分析

把复制的日志保存到仓库根目录的 `run.ndjson` 后：

```powershell
node tools/analyze-perf-log.mjs run.ndjson
```

生成 `run.analysis/`：

- `report.md`：阶段表、异常和解读说明。
- `phases.csv`：可直接导入表格软件。
- `summary.json`：完整指标和相对空窗口基线的差值。

日志包含源码哈希、客户端/宿主版本、画质相关选项、阶段负载、预热/采样时间、帧耗时、各 Lua 模块耗时、模型实际加载数、资源池数量、声音失败、逻辑补算丢弃以及错误。

`frameMs` 是实际 OnUpdate 间隔；`luaFrameMs` 是引擎 Lua 帧开销，不涵盖全部原生渲染/GPU 开销。P95/P99 是直方图近似上界，日志保留精度。`memoryKB` 来自共享客户端 Lua 堆，包含其他插件，不能归因到引擎或当作显存。

日志容量有界；空间不足优先保留阶段汇总，裁剪数量写在 `log.status`。模拟宿主日志默认被分析工具拒绝作为性能证据。

对比时固定地点、分辨率、画质、帧率上限和插件组合。基线指“空引擎窗口”，关闭引擎后的客户端基线需要另行记录。重复打开测试关注资源池是否趋稳，而不是要求 Frame 数量回到零。

## 调整与重新构建

```powershell
npm ci
npm run build
node tools/build-item-game.mjs items/performance-lab/item.json --verify-only
```

`content.json` 的 `benchmark.warmup / duration` 控制时间；`game.lua` 的 `stages` 控制负载档位。当前测试配置上限为1200实体、256活动粒子、16发射器、每个模型池40对象，JSON/任务/事件/日志也有限制。更大负载需同时调整合法配置与门槛，避免把资源拒绝误算成性能提升。

升级时保留 rootId、publisher、createdAt，增加 objectVersion 并更新 releaseVersion/savedAt。对外发布可传 `--previous <上一发行版 build-report.json>` 检查身份和版本；本地候选重建不自动宣称已发行。

## 需要在游戏内完成的验收

首次导入和使用、`/reload` 后启动、宏限制与键盘归还、两种模型画面和投影、声音可听性、Musician 设置副作用、真实存档持久化、双客户端交易与背包满/取消/断线、进入副本及销毁清理。仓库中的 mock 验证不能替代这些结果。
