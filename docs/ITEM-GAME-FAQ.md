# ItemGame 常见问题 FAQ

## 道具体积太大，或出现 package_not_included？

0.4.0 支持 `item.json.packages` 按需打包与 `build.profile: "release"` 源码精简。缺失能力时把提示中的包加入项目配置，重建并导入新版本；静态内容引用也会在构建时校验。选包、预算、锁、错误行号映射和日志策略见[包管理指南](ITEM-GAME-PACKAGES.md)。

接入看[开发指南](ITEM-GAME-DEVELOPER-GUIDE.md)，源码、构建和发布看[维护指南](ITEM-GAME-MAINTENANCE.md)。

## 宏提示“命令过长”，为什么没有 Lua 报错？

TRP3 宏编辑器限制 **255 字节**，不是 1023，也不是 255 个汉字；包含 `/run ` 和空格。宏被拦住后没完成注入，可能尚未进入引擎，所以没有引擎 Lua 错误。

旧宏约 731 字节，构建门槛设错；当前性能台宏是 253 ASCII 字节。重新导入完整新版，不要把引擎主体粘进宏。维护时检查 `build-report.json` 的 `sizes.macroBytes / macroLimit`；仅把 rootId 改长也可能超限。

## 为什么宏后面必须延时？

宏经过原生安全执行路径，紧接着的 Lua 可能在宏真正运行前执行。当前启动必须是三个节点：

```text
执行宏命令 → 原生延时 0.1 秒 → 执行限定 Lua
```

这是实机踩坑后的必需编排，已由构建器生成。不要删除第二个节点或用 Lua 忙等替代。宏只准备本根物品的单次注入，延时 Lua 才加载引擎；用完或两秒超时后恢复，不长期开启所有道具的执行能力。

## 右键后没有窗口，先看什么？

确认导入完整定义后已**添加到 TRP3 背包**；从主道具使用，不要单独预览 wf_open 或启动 Lua。更新旧版后执行一次 `/reload`。

| 聊天提示 | 位置 / 下一步 |
| --- | --- |
| 没有 `[IG 1/3]` | 尚未执行延时 Lua；查宏过长、信任提示、使用绑定和三步节点 |
| `[IG 1/3]` | 延时 Lua 已运行，还不代表注入成功 |
| `[IG CONTEXT]` | 缺少正确主道具实例；从背包使用主道具 |
| `[IG INJECTION]` | 没有 GUI 能力；查宏、延时及宿主脚本限制 |
| `[IG 2/3]` | 注入成功，开始装载引擎 |
| `[IG BOOTSTRAP]` | 装载/注册抛错；保留后面的错误原文 |
| `[IG OPEN]` | 配置、存档或建立场次失败；按后续原因处理，如版本不匹配或副本限制 |
| `[IG ENGINE]` | 直接调用了尚未装载的入口；从主道具 onUse 启动 |
| `[IG 3/3]` | onStart 完成且窗口已显示；0.1.4 起分别显示构建版本与本机道具修订号 |

最近提示保存在主道具 `IG_BOOT_STATUS_V1`。反馈附提示原文、对象版本、客户端/TRP3E 版本和使用入口；运行后故障再附复制日志。启动失败可以没有独立 Lua 错误框。

## 提示已打开，但窗口马上消失，日志是 definition_changed？

TRP3 原生编辑器每次保存会递增道具 MD.V，但包内 Lua 的 objectVersion 仍是构建时的值。0.1.3 及以前用这两个值比较，可能刚启动就把之前的编辑误判为“运行中定义变化”，随即关闭。

0.1.4 已改为记录本次启动的实际修订号，运行期间再次变化才关闭；清单更新仍会触发关闭。导入构建版本 5 并执行 `/reload` 后重试，不必手工把 MD.V 改回旧值。聊天分别显示构建版本和道具修订，它们可以不同。真正的运行中定义更新会显示 [IG STOP]，最近提示仍保留在 IG_BOOT_STATUS_V1。

## 为什么按 Esc 关不掉？

0.1.2 及更早的引擎只在接管模式下把 Esc 用作暂停，普通/暂停状态未注册魔兽的 Esc 关闭入口。0.1.3 已注册 UISpecialFrames，主界面在普通、接管、暂停状态都可用 Esc 关闭。日志或曲目输入框有焦点时，第一次 Esc 返回主界面，第二次关闭；右上角 X 始终关闭整个游戏。

日志面板现在会给 X 留出位置，拖动区也不覆盖 X。退出先隐藏窗口和释放输入；存档、统计或清理异常分别记录，不阻止其他清理步骤。日志中的 cleanup.* 错误及 [IG CLOSE] 提示用于定位未完成的清理。

更新测试道具到当前构建版本 6 后执行一次 `/reload`，再打开验证。旧版已卡住的界面也可先用 `/reload` 清理。

## 游戏里能直接导出日志文件吗？

不能创建任意电脑文件。**“复制日志”打开文本框，Ctrl+A/C 后在游戏外保存**，再交给 `tools/analyze-perf-log.mjs`。

日志也写入主道具 `IG_PERF_LOG_V1`。WoW 在正常退出或 `/reload` 等时机把 TRP3 数据写入 SavedVariables；变量写入成功只是内存值已核对，不代表即时刷盘。当前没有 SavedVariables 自动提取工具。删除主道具会失去其数据，先复制要保留的日志。

## 为什么导入后没存档，或者同名道具进度不同？

- **根定义/内部定义**描述引擎、配置和类型；导入码主要登记定义。
- **背包实例**持有这份道具的变量和数量；两份主道具可以有不同进度。
- **运行 session**持有当前实体、窗口和声音；关闭不等于删除存档。

`IN.ig_game` 是共享配置，不能保存玩家进度。进度写主道具 `o` 变量，不依赖 `c` 战役变量。原生交易实例与分享定义不同，不能假定导入串也带作者进度。

## 为什么主道具不能堆叠？

上游拆堆不复制实例变量，合堆也不按变量区别内容。主道具、带属性装备必须禁止堆叠；同质材料才用数量。不要靠堆叠数量编码经验或词条。

## 存档版本不匹配，要清空变量吗？

不要先清空。引擎保留不匹配存档并拒绝覆盖，坏格式才尝试有效备份。保留原物品/变量，让维护者提供迁移。改玩法数值不必改 saveVersion；新游戏也不能借旧 rootId 更新。

## 接管按键会驱动 WoW 角色吗？

不会输出系统按键。`input.emitAction` 只提交小游戏动作；`readKey` 读取宿主允许查询的键，不可用时可返回 nil。默认读取/透传；主动接管后拦截配置中的游戏按键，其他键可透传。聊天、日志、曲目文本面板、暂停退出会释放控制。

WoW 战斗、地下城、团队副本、场景战役、战场或竞技场会关闭小游戏；住宅 interior/neighborhood 允许启动。脱战/出本不自动重开。

## 模型 loaded=true，为什么不算全部验收？

它只表示后端加载状态，不证明镜头、方向、尺寸和动画正确。当前支持 PlayerModel 与共享 ModelScene，资源用 creatureDisplayID 或 fileID，表现受客户端版本影响。

`assets.recordModels()` 记录文件 ID、加载状态、逻辑框及可用时的 Actor 包围盒。包围盒不替代战斗碰撞体，PlayerModel 也不保证给出同样信息。当前碰撞是 AABB/扫掠 AABB；复杂刚体、圆形、多边形和完整资产浏览器尚未实现。

## 音效正常但 BGM 没声音，是音乐文件坏了吗？

不一定。首轮实机日志 `Sound_EnableMusic=0`，音效走 SFX，所以音效正常而 Music 失败。修复后的原生 BGM 默认走 **SFX**；曲目可显式设 `channel: "Music"`。引擎不修改全局音频设置，仍遵守总声音开关、所选通道开关和音量。

新候选会记录实际通道、资源和播放结果；检查音频设置后再试听。API 返回成功不等于耳听确认；精确错误提示见[性能台说明](../items/performance-lab/README.md)。

## 必须安装 Musician 吗？能直接播放 MIDI 文件吗？

玩法、Sound、WoW 内置 BGM 不依赖 Musician。自定义曲目是可选增强：开发时准备 Musician 曲目数据，写 `music.<id>.musicianCode`，或用测试台的手动导入入口；`nativeFileId` 可提供回退。

IG 0.2.6 默认自动优先 Musician，未加载插件、插件忙碌/静音或曲目加载失败时使用原生回退；游戏可调用 `ctx.music.setBackend("native")` 强制原生，或 `setBackend("auto")` 恢复自动，并自行保存偏好。生物大战天灾在游戏设置中提供该切换。MIDI 使用乐谱游标暂停续播，但独立百分比音量只适用于原生 BGM；MIDI 模式不会为了调低音量而随机换曲。

当前没有通用 MIDI 合成器，也不能将电脑 `.mid` 路径当作道具可读取的文件。Musician 版本、曲目格式和音频设置需单独验证；只播本机 BGM，不自动广播演奏。

## 自动基准结束，是否引擎全部通过？

“到达结束”和状态 complete 不同，music_not_started/models_not_verified 不算对应能力成功。先看实际负载、加载数、错误和日志裁剪，再分析性能。

首轮样本支持该客户端启动和自动负载运行，未覆盖双客户端交易、重登存档、进本关闭和长期清理。frameMs 包含客户端整体影响，luaFrameMs 是引擎 Lua 用时；共享 Lua 堆不是引擎独占内存。比较时固定环境并保留候选 sourceHash。
